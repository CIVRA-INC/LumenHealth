# ADR 0007: Identifiers and synchronisation readiness

**Status:** accepted · **Date:** 2026-10-23

## Decision

- Primary keys are **UUIDv7**, generated by the application (Prisma `uuid(7)`): unique without coordination and time-ordered for index locality. Patient-facing identifiers are separate (MRN `LH-000123`, per-organisation sequence from an atomic counter).
- Mutable aggregates carry `version` (optimistic concurrency) and `updatedAt`; all instants are `timestamptz` in UTC; calendar-only values use `date`.
- Every row has an owning organisation; clinical rows also carry `patientId`, `branchId` where relevant, and creator/updater user ids: the inputs a sync engine needs for ownership and conflict policy.
- No sync engine is built now (see `architecture/offline-sync.md`).

## Consequences

Rows can later be created on a facility-local node without id collisions. MRN allocation is a central-authority concern and will need a block-allocation or provisional-id strategy for offline use (documented, deferred).
